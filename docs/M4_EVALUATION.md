# LocalView M4 评估报告

## 1. 结论

M4 已完成。LocalView 从本地服务启动器扩展为可直接预览 localhost 页面的小型开发工作台。用户可以在项目详情页启动服务，并在同一窗口内加载页面、输入 localhost 地址、前进、后退、刷新或交给系统浏览器打开。

## 2. 已交付能力

### 2.1 内嵌页面预览

- 使用桌面 WebView 内嵌 iframe 渲染项目 URL。
- 页面预览与当前项目绑定，切换项目会重置地址和历史栈。
- 支持开发服务器常见的 HMR/WebSocket 场景，预览容器不增加 sandbox 限制。
- 地址栏只接受 `http`/`https` 的 `localhost`、`127.0.0.1` 和 `::1` 地址，保持 LocalView 的产品边界。

### 2.2 导航控制

- 后退、前进、刷新按钮。
- 地址栏回车导航。
- 当前地址可通过“在浏览器中打开”交给系统浏览器。
- 前进/后退按钮根据本地导航历史自动禁用，避免无效操作。

### 2.3 预览状态

预览区域区分以下状态：

- 服务尚未启动；
- 正在等待端口就绪；
- 页面加载中；
- 页面已加载；
- 服务已停止；
- 页面加载失败。

状态由 M3 的运行时事件驱动，服务停止或异常退出后，预览区域会及时切换到对应状态页。

### 2.4 调试工作台布局

- 预览区域置于项目控制区之后，日志面板继续保留在下方。
- 预览工具栏包含状态指示、导航控制和地址栏。
- 页面加载期间显示轻量加载提示；空状态和错误状态提供明确的下一步操作。
- 中英文文案均维护在 `src/i18n.tsx`，没有新增硬编码 UI 文案。

## 5. 已知边界

M4 采用 iframe 作为内嵌预览容器，因此跨源页面的浏览器内部历史由 LocalView 自己维护，无法读取页面内部的真实 history 状态；复杂项目的 DevTools 仍建议使用外部浏览器。下一阶段 M5 将重点验证 Vite、Next.js 等真实项目的 HMR、WebSocket、错误页、跨平台 WebView 差异和安全策略。
